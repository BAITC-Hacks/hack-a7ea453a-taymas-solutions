# План запроса недостающих данных (PAN-54)

В панели Copilot раскройте **«Каких данных не хватает?»**. План относится к
выбранному на графе/в поиске узлу. Если выбора нет, используется первый gid
из контекста, затем первый кандидат ответа. Целевой gid всегда подписан и
открывает существующую карточку. При смене узла план пересчитывается.

Это локальный план проверки: запросы не отправляются. Он работает при
недоступном API Copilot и без NVIDIA. Демо-набор явно помечается.

## Реализация и контракт

`frontend/src/investigation/dataRequestPlan.ts` экспортирует чистую функцию
`buildDataRequestPlan(data: GraphData, gid: string): DataRequestPlan`.
Она читает уже загруженные CSV, ничего не записывает, не меняет входные
данные и не вычисляет роль/приоритет. Gid не преобразуется в Number.
Подключение к существующему UI — импорт и один компонент в CopilotPanel;
App, стили основного экрана, API и Python pipeline не изменяются.

Результат имеет `schema_version: 1`, `gid`, `status`, `message`, `items`,
`coverage`. Статусы: `ready`, `insufficient_data`, `unknown_gid`.
Каждый пункт содержит:

- стабильный `id` из gid и вида рекомендации, `kind`, `title`;
- `observed`, `limitation`, `hypothesis`;
- `request`: направление, период, требуемые поля и цель;
- `supports` / `weakens`: наблюдения, которые поддержат/ослабят гипотезу;
- `sources`: файл, колонка, gid либо src/dst и исходное значение.

Источником является текущий снимок GraphData. При будущем сохранении в дело
(PAN-52) вызывающий слой должен прикрепить версию/отпечаток снимка. Этот модуль
не хранит историю и не заявляет совместимость старого плана с новой выгрузкой.

## Правила и ограничения

| Сигнал | Рекомендация | Источник |
|---|---|---|
| depth=4 или явный boundary_depth4 | Полная исходящая выписка | nodes_roles.csv |
| is_seed / in_underestimated | Полная входящая выписка и начальный остаток | nodes_roles.csv |
| external_inflow_suspected | Тот же запрос с основанием о возможном внешнем источнике | nodes_roles.csv |
| Подтверждённые входящий и исходящий переводы в один день | Время исполнения и часовой пояс, если доступны | first_date/last_date в edge_table.csv |

Для неполного входа используется готовый флаг PAN-50. Порог 1.2 здесь не
дублируется и не подменяется новым. Несколько оснований входящего запроса
объединяются, а ограничения входа, выхода и времени сохраняются раздельно.
Превышение оттока само по себе не доказывает невидимое поступление: его
может покрывать начальный остаток. Исходящая выписка без переводов не
доказывает размер остатка или отсутствие других способов расходования.

`first_date` и `last_date` подтверждают событие на соответствующую дату.
Совпадение одного из концов входящего диапазона с концом исходящего даёт
свидетельство двух операций в один день. Просто пересекающиеся диапазоны,
`median_lag_days=0` и `fast_out_share` не используются как свидетельство.
Самоперевод не считается двумя разными событиями. Неверные/обратные диапазоны
пропускаются. Выбирается один воспроизводимый пример: самый ранний день и
затем пары по строковому src/dst. Это не полный поиск по transactions.parquet;
остальные совпадения потребуют будущего дневного слоя PAN-53.

Порядок внутри дня неизвестен. Более точные даты могут проверить временную
совместимость, но не идентичность денег. Результаты — гипотезы, не оценка вины.

Для выписок период задан как `scope: source_period`: полный период исходной
выгрузки. Минимальная и максимальная наблюдаемые даты не выдаются за границы
этого периода. Для временного запроса используется `scope: day` с доказанной
датой. Ни год/месяц, ни gid не зашиты в производственные правила.

Если диагностического флага или корректных дат нет, рекомендация по ним не
создаётся. Пустой план сообщает о недостаточности оснований, а не о полном
охвате данных. CSV-тексты evidence/why не используются для генерации правил.

## Проверки и демо

В `frontend/`:

```bash
npm ci
npm test
npm run build
npm run dev -- --host 127.0.0.1 --port 5184
```

В другом терминале, при наличии локальных `out/`:

```bash
COPILOT_UI_URL=http://127.0.0.1:5184 npm run test:e2e -- data-request.spec.ts
```

Unit-тесты проверяют источники, флаги False из CSV, объединение оснований,
точность gid, даты, отсутствие мутаций и независимость от API. При наличии
реальных out/ дополнительный тест прогоняет все узлы через штатный CSV-адаптер
и сверяет каждую ссылку на факт. Без out/ только эта проверка пропускается.
Браузерный тест выбирает gid из данных, принудительно отключает API, проверяет
смену плана, источники, переход в карточку и сохранение рабочего графа.

Демо: выбрать depth=4 → открыть план → показать исходящий запрос и условия
проверки → выбрать узел с неполным входом → показать альтернативу с начальным
остатком и ссылки на источники. Отдельно можно показать запрос времени у узла
с подтверждёнными операциями в один день.
