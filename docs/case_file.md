# Локальное дело расследования (PAN-52)

Дело объединяет снимки выбранных клиентов и проверенных ответов Copilot,
рабочую гипотезу и отдельные заметки аналитика. Оно встроено в интерфейс
Taymas: значок папки в левой навигации открывает дело и показывает число
сохранённых материалов. Граф, фильтры и последний ответ остаются на месте
при переключении между исследованием и делом.

## Сценарий работы

1. Выберите клиента в очереди или на графе. В карточке нажмите **«Добавить узел
   в дело»**. Сохраняются его числовые признаки, роль, приоритет, источники,
   оговорки и следующие шаги из локального плана PAN-54.
2. Задайте вопрос Copilot и нажмите **«Сохранить ответ в дело»**. Повторите с
   другим вопросом: в деле остаются оба ответа. Сохраняются проверенные
   структурированные claims, включая направленные связи и источники, а текст
   ответа хранится отдельно как гипотеза/объяснение.
3. Откройте папку дела. Дайте ему название, запишите рабочую гипотезу и заметки.
   Они визуально отделены от фактов: гипотезы — янтарным акцентом, заметки —
   сиреневым; у сверенных фактов — зелёная отметка и ссылка на колонку CSV.
4. При необходимости удалите материал; последнее удаление можно отменить
   кнопкой уведомления. Перезагрузка восстанавливает сохранённый состав дела,
   точные gid, гипотезу и заметки.
5. **«Скачать JSON»** сохраняет переносимый файл. **«Импорт дела»** сначала
   проверяет его схему и показывает название/число материалов. Только кнопка
   **«Заменить дело»** заменяет текущую сессию. Некорректный файл её не меняет.
6. **«Печатная справка»** скачивает самостоятельный HTML. Откройте его в
   браузере, выберите печать → «Сохранить как PDF». В справку входят все факты,
   в том числе свёрнутые в интерфейсе, длинные gid, суммы с единицами,
   источники, полные отпечатки, гипотезы, заметки, следующие шаги и оговорки.

Повторное добавление того же узла в той же версии данных не создаёт дубликат.
Одинаковые вопрос и содержимое ответа тоже не дублируются. Другой вопрос,
изменившийся ответ или другая версия данных создают отдельный снимок.

## Что именно подтверждено

При сохранении ответа повторно вызывается существующий `validateAnswer`
из `copilot/api.ts`: gid, значения и источники должны соответствовать данным,
открытым на экране. Ошибочный ответ или `verification != passed` не сохраняется.
Для карточки используются поля существующего `NodeRecord`, без пересчёта
роли или приоритета; каждый факт указывает `nodes_roles.csv`, gid и колонку.

При восстановлении и импорте не доверяем сохранённой отметке проверки.
`snapshotStatus` проверяет отпечаток и размеры набора и повторно сверяет
структурированные claims через тот же валидатор. Текст гипотезы, объяснение
роли, заметки и следующие шаги не получают статус подтверждённых фактов.
Проверка чисел не является семантической проверкой произвольного текста.

| Состояние | Что показывает дело |
|---|---|
| `current` | Факты сверены с текущими CSV; gid открывается в текущем графе |
| `stale` | «Снимок другой выгрузки»; сохранённые значения доступны, переход в текущий граф отключён |
| `unavailable` | Текущая выгрузка ещё не загружена или недоступна; снимок можно читать и экспортировать |
| `unverified` | Отпечаток совпадает, но значения/ссылки/размеры не прошли сверку; зелёной отметки нет |

Ни импорт, ни открытие другого набора не переписывают старые факты. Материалы
разных версий могут находиться в одном деле; версия хранится у каждого.
Статус вычисляется заново и не импортируется из JSON. В печатной справке
статус фиксируется на момент экспорта и относится только к указанной версии.

## Отпечаток набора

`fingerprintData` вычисляет SHA-256 канонического представления всех четырёх
загруженных таблиц: узлов, рёбер, кластеров и top-list. Учитываются все доступные
колонки, строки сортируются по канонической записи, ключи объектов — по имени.
Смена порядка строк/колонок или URL не меняет отпечаток. Изменение значений
любой таблицы меняет его. Числа уже нормализованы существующим CSV-адаптером.

Это **отпечаток загруженных данных**, а не побайтовый SHA-256 файлов:
переносы строк, CSV-кавычки и эквивалентное форматирование чисел его не меняют.
Отчёт pipeline остаётся источником побайтовых хешей. Отпечаток дела не является
цифровой подписью и не доказывает авторство импортированного файла.

При смене объекта `GraphData` версия вычисляется заново; до её готовности
сохранение новых материалов недоступно. Запоздавшее вычисление старой версии
отбрасывается. Это отдельный слой поверх готовых CSV: загрузка Parquet PAN-58
и серверный протокол не меняются.

## JSON, сохранение и безопасность

`schema_version: 1`. Верхний уровень содержит только:

```text
schema_version, id, title, created_at, updated_at, hypothesis, notes, items
```

Каждый `items[]` содержит:

```text
id, kind (node | copilot), title, created_at,
dataset { id: "sha256:<64 hex>", node_count, edge_count },
gids (строки), claims (структурированные Claim/Source PAN-48),
hypothesis, warnings [{ code, message, gid? }], next_steps
```

`parseCase` — строгий валидатор и конструктор разрешённой схемы. Проверяются
типы, конечность чисел, ISO-даты, размеры, уникальность id, строковые gid
из 1–19 цифр, соответствие kind/source/file/column и ссылки на gid внутри
материала. Неизвестные поля, в том числе `__proto__` и API-конфигурация,
отклоняются на всех структурных уровнях. Версия схемы, отличная от 1,
отклоняется без попытки угадать формат. Будущие миграции должны быть явными.

Ограничения: 100 материалов на дело, файл до 4 000 000 байт UTF-8, название
до 200 символов, гипотеза и заметки аналитика — до 20 000 символов каждое.
Для материала: до 1000 gid/claims/warnings/следующих шагов; гипотеза до 4000,
вопрос/предупреждение/шаг до 1000 символов. Лимиты импорта и экспорта совпадают.
JSON с числовыми gid отклоняется: JS Number теряет точность длинных gid.

Автосохранение выполняется после изменения в `localStorage` под ключом
`taymas.casebook.v1`. Приложение хранит одно открытое дело на origin браузера;
другие дела можно держать в JSON. При смене порта/домена хранилище другое.
Общая работа нескольких вкладок и слияние одновременных правок не реализованы.

При запрете/переполнении хранилища изменения остаются в памяти, появляется
предложение скачать JSON. Ошибочная старая запись не перезаписывается самим
открытием страницы. Скачанный JSON — переносимая копия; очистка браузерного
хранилища удаляет локальное дело.

В экспорт попадают только поля схемы, а не сырой ответ сервера, заголовки,
параметры провайдера, переменные окружения или API-ключи. Произвольный текст
заметок сохраняется как текст пользователя. React экранирует его; генератор
справки экранирует все динамические значения. HTML не содержит скриптов,
внешних ресурсов или обработчиков событий и задаёт CSP `default-src 'none'`.
Текст `<script>`/HTML из заметок отображается буквально и не выполняется.

## Локальная работа и ограничения

Для дела не нужны NVIDIA, облако или сетевые запросы: сохранение, импорт,
проверка по уже загруженной таблице и экспорт выполняются в браузере.
Ответы Copilot можно получать от локального fallback без API-ключа.
Для первоначальной загрузки самого приложения нужен его локальный HTTP-сервер;
service worker/offline-кэш приложения не добавляется. Web Crypto доступен
на localhost или HTTPS. При недоступности SHA-256 сохранение новых фактов
блокируется с объяснением, уже сохранённое дело остаётся доступным.

Дело не меняет исходные данные, роли, priority_score, CSV или Python-pipeline.
Глубина 4, неполный вход seed, внешние плательщики, порог 5 000 KZT и дневная
точность дат остаются ограничениями выводов. Приоритет не является вероятностью
вины; роль и гипотеза требуют самостоятельной проверки аналитиком.

## Проверки и демо

```bash
# Из корня, отдельные терминалы:
python -m money_graph --data data --out out --check-repro
python -m agent_orchestrator.server --out out
cd frontend && npm ci && npm run dev -- --host 127.0.0.1 --port 5178

# Проверки frontend:
cd frontend
npm run build
npm test
COPILOT_UI_URL=http://127.0.0.1:5178 npm run test:e2e
```

Unit-тесты проверяют round-trip узла/двух ответов/связи, точность gid,
неизменность отпечатка от перестановки строк, изменение каждой таблицы,
подмену факта при совпадающем отпечатке, плохую схему/JSON, источники,
дубликаты, лимит размера, отсутствие API-полей и безопасный HTML с длинным текстом.
Компонентные тесты проверяют восстановление, удаление/отмену, заметки, замену
при импорте, устаревшие снимки, повреждённое и недоступное хранилище.

E2E на реальных CSV проходит: карточка → узел в дело → два локальных ответа
→ заметки → JSON и HTML → удаление/отмена → перезагрузка → повреждённый и
корректный импорт → смена CSV → явная маркировка старых снимков. Снимки экрана
для desktop, mobile и печати сохраняются в `frontend/test-results/`.

Короткое демо: выберите первый приоритет, добавьте клиента и два ответа на
разные вопросы; откройте дело, покажите источники и версию, запишите отдельную
гипотезу/заметку, скачайте JSON и HTML, перезагрузите страницу. Для проверки
устаревшего снимка импортируйте дело после загрузки другой выгрузки.
