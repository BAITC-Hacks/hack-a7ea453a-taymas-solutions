# AML Investigation Copilot: оркестратор (PAN-46)

`agent_orchestrator` отвечает на вопрос аналитика через локальные инструменты PAN-45.
Он возвращает проверяемый brief: gid, роль, приоритет, суммы, число переводов,
ссылки на конкретные строки и колонки CSV, ограничения данных и следующий шаг.
Каждый аналитический ответ содержит «гипотеза для проверки».

Основной `python -m money_graph` не импортирует оркестратор и работает независимо
от него. PAN-46 не меняет выгрузки, формулы, React или основной пайплайн.

## Подключение

Python 3.11, обычный `requirements.txt`; внешнего LLM SDK нет.
Для запросов к реальным данным нужен пакет `agent_tools` из **PAN-45**;
общий контракт представления brief берётся из `agent_tools.answer` (PAN-62).
Для дополнительной сверки с CSV нужен `agent_tools.verifier` из **PAN-47**.
Они разрабатываются отдельными PR; PAN-46 их код не копирует.

```python
from agent_tools import GraphStore, GraphTools
from agent_orchestrator import answer, for_browser

tools = GraphTools(GraphStore.from_dir("out"))
primary_gid = int(tools.store.top.gid.iat[0])
brief = answer("Почему этот узел в топе?", tools, selected_gids=[primary_gid])
payload = for_browser(brief)  # перед отправкой в React обязательно!
```

Python-ответ совместим с контрактом `agent_tools.answer.ANSWER_SCHEMA` PAN-47:
gid — точные целые int64. `for_browser` переводит **все** gid, src, dst, списки gid,
включая ссылки на источники и аргументы инструментов, в десятичные строки.
JavaScript Number не сохраняет точность идентификаторов этого датасета.
Роли, score, суммы и счётчики остаются исходными значениями.

CLI читает готовые выгрузки и печатает JSON в stdout, файлы не создаёт:

```bash
python -m agent_orchestrator --out out --question 'Кого проверить первым и почему?'
python -m agent_orchestrator --out out --question 'Почему этот узел в топе?' --gid "$SELECTED_GID"
python -m agent_orchestrator --out out --question 'Кто общий сборщик?' --gid "$PAYER_A" --gid "$PAYER_B"
```

Без PAN-45 CLI возвращает `tools_unavailable`, без готовых CSV — `outputs_unavailable`.
Успех и осмысленный пустой результат дают exit code 0, typed error — 2.

## Вопрос → инструменты

| Вопрос | Маршрут | Локальные вызовы |
|---|---|---|
| Почему узел в топе / какова роль? | `explanation` | `get_node` для каждого выбранного gid |
| Кто собирает деньги с этих gid? | `common_collector` | `compare_nodes` + `find_common_collectors` |
| Какой следующий шаг? | `next_step` | карточки выбранных узлов, входящие и исходящие первого выбранного gid |
| Кого проверить первым? Без выделения узлов | `next_step` | `rank_candidates(limit=5)` |
| Откуда пришли / куда ушли деньги? | `trace` | карточка, крупнейшие прямые переводы и ограниченный обход в нужном направлении |
| Неизвестный вопрос | `other` | без вызовов инструментов и NVIDIA, typed error с подсказкой |

Вопросы распознаются на русском и по основным английским формулировкам.
Это ограниченный router для заданных сценариев, не универсальное понимание языка.
В частности, произвольные суммы/фильтры из текста не превращаются в запросы к данным.

Выбор из UI имеет приоритет: gid, явно написанный в вопросе, должен входить в выделение.
Без выделения распознаются длинные идентификаторы из вопроса либо список после `gid:`.
Числа вроде суммы перевода или глубины автоматически не считаются идентификаторами.
Для карточки нужен хотя бы один gid; для сборщика — два; для обхода — ровно один.
Глубина задаётся полем `depth`, по умолчанию 2, допускается 1–4.

Общий сборщик означает достижимость минимум из двух заданных источников в пределах
выбранной глубины. Сортировка кандидатов сохраняется из PAN-45: число источников,
прямая сумма, priority_score, gid. Суммы через посредников не приписываются источнику:
в claims попадают только наблюдаемые **прямые** рёбра.

## Контракт для PAN-48

`Request.from_dict(payload)` отклоняет неизвестные поля и неправильные типы.
Вход: `question`, необязательные `selected_gids`, `depth`, `use_nvidia`.
Схемы: `agent_orchestrator.schemas.REQUEST_SCHEMA`, `ANSWER_SCHEMA` и
`BROWSER_ANSWER_SCHEMA` (JSON Schema 2020-12, `additionalProperties: false`).

| Поле ответа | Как отображать |
|---|---|
| `status` | `ok`, `empty` или `error`; пустой результат не означает сбой |
| `provider` | `fallback` либо `nvidia`; индикатор фактически использованного режима |
| `summary` | Строгое представление типизированных claims через `render_summary`; произвольный текст не принимается |
| `candidates` | Упорядоченные `{gid, role, priority_score}` для карточек |
| `claims` | Все факты: `kind=node/edge`, идентификаторы, `field`, `value`, точный `source` |
| `evidence` | `{claim_index}` — индексы в `claims`, которые следует показать с акцентом |
| `sources` | Ссылки `{file, gid/src/dst, column}` для проверки фактов |
| `gids` | Все идентификаторы, использованные в фактах; для переходов и подсветки |
| `tool_calls` | Реально выполненные graph tools с аргументами |
| `warnings` | Ограничения выгрузки, seed-вход, граница обхода и усечение списков |
| `next_steps` | Действия аналитика: выписки, сверка плательщиков, продолжение обхода |
| `verification` | `passed` после PAN-47; `unavailable` без PAN-47; `not_applicable` для ошибки |
| `fallback_reason` | Причина переключения: `no_api_key`, `no_model`, `timeout`, `quota` и др.; `null` для обычного локального ответа |
| `error` | `null` либо `{code, message}` с понятным сообщением |

PAN-62 связывает summary с полями конкретных узлов и направленных рёбер, а не с
общим набором чисел. Verifier пересобирает summary тем же шаблоном и отклоняет
расхождение. `next_steps` содержит только значения `agent_tools.answer.NEXT_STEPS`.
Это ограниченный контракт отображения, не семантическая проверка любого текста:
гипотезы о роли и полезности следующего действия всё равно требуют проверки аналитиком.

`evidence` ссылается на факты, а не содержит свободный непроверенный текст модели.
Подсвечиваемые рёбра берутся из claims с `kind=edge`. UI не должен интерпретировать
`summary`, строки вопроса или поля CSV как HTML.

## NVIDIA: явное включение, безопасный fallback

Конфигурация читается только из окружения: `NVIDIA_API_KEY`, `NVIDIA_MODEL`.
Модель не зафиксирована в коде; выберите доступную в аккаунте модель с function calling.
Не передавайте ключ в аргументе CLI и не добавляйте его в репозиторий или Docker image.

Наличие ключа само по себе не запускает сеть. Для конкретного вопроса нужны
`answer(..., use_nvidia=True)` или флаг CLI `--nvidia`.

Протокол использует [NVIDIA Chat Completions API](https://docs.api.nvidia.com/nim/reference/qwen-qwen3-5-122b-a10b-infer):
фиксированный HTTPS endpoint `https://integrate.api.nvidia.com/v1/chat/completions`,
Bearer credential, `messages`, `tools`, ограничение `max_tokens`.
SDK и внешняя зависимость не требуются. Redirect, poll, retry и streaming отключены.

1. Router определяет сценарий и допустимый план по выделению аналитика.
2. NVIDIA получает вопрос, выбранные gid и конкретные допустимые вызовы.
   Параметры ограничены JSON-схемой; ответ повторно проверяется в Python.
   Модель не может расширить список gid, глубину, лимиты или набор функций.
3. Локальные graph tools выполняются один раз; из результатов строится brief.
4. PAN-47, если установлен, сверяет claims с CSV. Ошибка проверки скрывает факты.
   Replay инструментов внутри verifier отключён в его копии ответа: все числа
   уже представлены claims, а вызовы прошли проверку router/PAN-45.
5. NVIDIA получает до 24 типизированных фактов о выбранных узлах, найденных кандидатах
   и прямых рёбрах. Она может выбрать до пяти существующих claim indices и одно
   действие из словаря. Свободный текст, новые факты и значения модели не публикуются.
   Поэтому provider=`nvidia` означает **выбор акцентов и действия**, а summary остаётся
   сформированным локально. Ранжирование кандидатов от модели не зависит.

Данные передаются в отдельном `DATA`-блоке. Свободные `evidence` / `priority_why`
из CSV, весь датасет, store, история чата и секреты в модель не передаются.
Найденные локальными инструментами соседи и сборщики — допустимое ограниченное
расширение исходного выделения. Глобальный рейтинг запрашивается только для
«кого проверить первым» без выбранных gid.

При отсутствии конфигурации, 429, timeout, 401/403, другом HTTP-сбое, неполном
или неверном ответе показывается тот же локальный brief. Результаты graph tools
повторно не вычисляются. Если невалидны сами локальные факты, возвращается
`invalid_evidence` с пустыми claims, а не выдуманный fallback.

## Ограничения

| Ограничение | Значение |
|---|---:|
| Вопрос | 1000 символов |
| Выбранные gid | 5 |
| Graph tool calls | максимум 8, текущие планы используют не больше 7 |
| Кандидаты / рёбра в каждом запросе | 5 |
| NVIDIA-запросы | максимум 2, без повторов |
| Ответ модели | максимум 768 токенов и 32 000 байт |
| Полный HTTP payload, включая схемы | максимум 24 000 байт |
| Сетевой timeout | до 8 секунд, второй запрос получает остаток бюджета |
| Brief | максимум 100 000 байт UTF-8 |

Пределы применяются до вызова инструмента/API и до возврата brief.
Усечённый список имеет предупреждение; отсутствие узла в нём не доказывает его
отсутствие в графе. Граница 4-го колена и неполнота входа seed остаются видимыми
и не могут быть подавлены моделью.

Лог содержит только intent, provider, status, количество вызовов, код fallback
и длительность. Текст вопроса, gid, данные, HTTP bodies и ключ не логируются.
В allow-list нет записи файлов, shell, внешнего обогащения или изменения score.

## Проверки

```bash
python -m pytest tests/test_orchestrator.py -q
# После подключения PAN-45 и PAN-47:
python -m pytest tests/test_orchestrator_integration.py -q
python -m agent_tools.evaluation --out out --answerer agent_orchestrator.orchestrator:answer_case
```

Unit-тесты работают без agent_tools, ключа и сети. Они проверяют маршруты, пределы,
точность gid, opt-in, неизвестный intent, пустые результаты, неподтверждённые факты,
подмену инструмента/аргументов, инъекции в CSV, размер контекста и HTTP-ответа,
timeout/quota/auth/redirect, неполный ответ и отсутствие секретов в логах.

Интеграционные тесты используют настоящий пайплайн и graph tools, включая пять
вопросов PAN-47 на реальных данных: priority, common collector, trace, depth4, empty.
Проверяются исходные таблицы до/после и ответы локального режима и имитации NVIDIA.
Без PAN-45/PAN-47 этот модуль тестов явно пропускается; это не проверка интеграции.

Live-запрос с NVIDIA — отдельный smoke при настроенном окружении:
`python -m agent_orchestrator --out out --question 'Кого проверить первым и почему?' --nvidia`.
Для подтверждения live-успеха нужны `provider=nvidia`, `status=ok`, `fallback_reason=null`.
Успешный fallback сам по себе доступность NVIDIA не подтверждает.
