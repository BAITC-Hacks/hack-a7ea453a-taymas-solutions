# Проверка CSV в интерфейсе (PAN-64)

Перед показом графа браузер проверяет все четыре CSV как один набор. При ошибке загрузка отклоняется целиком: сообщение содержит файл, физическую строку CSV и поле. Например: `edge_table.csv: строка 2, поле «n_tx»: ожидается целое число…`. Неизвестные рёбра не удаляются молча; нечисловые значения не превращаются в нули.

## Обязательные значения

- `gid`, `src`, `dst` — десятичные int64. Идентификаторы хранятся строками; проверка диапазона использует BigInt, а не Number.
- `role` — одно из шести значений словаря проекта; `role_score` и `priority_score` — конечные числа в диапазоне 0–1.
- `cluster_id` — неотрицательное безопасное целое; `rank` — последовательные целые от 1; `n_tx` — целое от 1; `n_nodes` — целое от 1; `n_seed` — неотрицательное целое.
- `sum_kzt` — конечная положительная сумма; `sum_kzt_internal` — конечная неотрицательная сумма.
- `evidence`, `why`, `hypothesis`, `top_gids` не пусты; `evidence` не превышает 200 символов.
- Пустые, повторяющиеся заголовки, незакрытые кавычки и строки с неправильным количеством полей отклоняются. UTF-8 BOM, CRLF, кавычки внутри текста и многострочные объяснения поддерживаются.

## Согласованность файлов

Узлы и кластеры уникальны. Оба конца каждого ребра существуют; каждая направленная пара представлена один раз. Обратное ребро — отдельная допустимая связь. Каждый узел ссылается на существующий кластер, а `n_nodes` совпадает с фактическим числом его узлов. `n_seed` сверяется с узлами, когда необязательный столбец `is_seed` присутствует; всегда проверяется `n_seed ≤ n_nodes`.

Внутренний оборот кластера сверяется с рёбрами его участников с допуском 0,01 KZT и поправкой на машинное округление. `top_gids` разделяется точкой с запятой: все идентификаторы уникальны и принадлежат соответствующему кластеру. Необязательные `hub_in_gid`/`hub_out_gid` также должны принадлежать кластеру.

У каждого узла топ-листа совпадают роль и приоритет с `nodes_roles.csv` (допуск приоритета 0,000001). GID в топ-листе уникальны, ранги последовательны, приоритеты идут по убыванию. Минимум 20 строк проверяет Python-пайплайн; интерфейс поддерживает небольшие демонстрационные наборы.

## Необязательные столбцы

Минимальная схема из ТЗ остаётся допустимой. Отсутствующие необязательные признаки сохраняют прежние значения отображения интерфейса: 0 для счётчиков/сумм и false для флагов. Это совместимость с минимальными CSV, а не восстановление недостающих банковских данных. Если известный столбец передан, его значения проверяются: счётчики целые и неотрицательные; глубина 0–4; суммы неотрицательные и конечные; булевы флаги true/false, 1/0 (также yes/no, да/нет).

Пустые значения допустимы только для аналитических метрик, которые пайплайн оставляет неопределёнными: `top_payer_share`, `top_receiver_share`, `fast_out_share`, `pass_through`, `pass_through_reliable`, `median_lag_days`. Они сохраняются пустыми. Значение `pass_through > 1` допустимо: исходящие могут превышать наблюдаемые входящие. Неизвестные дополнительные столбцы сохраняются как текст.

`edge_table.csv` с одними заголовками допустим для графа из изолированных узлов. Другие обязательные таблицы должны иметь строки.

## Проверка

```sh
cd frontend
npm ci
npm test
npm run build
```

Для дополнительной проверки локальных реальных выгрузок:

```sh
MONEY_GRAPH_TEST_OUT=/absolute/path/to/out npm test -- tests/csv-validation.test.ts
```

Отрицательные тесты покрывают повреждённые значения, дубликаты, неизвестные связи, несогласованные топ-листы и кластеры. Положительные — минимальную схему, большие близкие GID, изолированные узлы, nullable-метрики и демо-набор. Две суммы в демонстрационном `clusters.csv` исправлены по его собственным рёбрам: 8 920 000 и 0 KZT; реальные выгрузки не изменяются.
