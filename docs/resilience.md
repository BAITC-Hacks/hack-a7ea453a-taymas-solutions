# Устойчивость сети при удалении узлов (PAN-44)

Бонусный эксперимент: гипотеза о том, что AML-приоритет выделяет узлы,
поддерживающие структуру наблюдаемой сети. Сравнение проверяет эту гипотезу,
а не предполагает её истинность. Модуль `analytics/resilience.py` автономен:
не импортирует `money_graph`, не требует ролей, не изменяет скоринг и не пишет
на диск. Основной pipeline и три обязательные выгрузки от него не зависят.

## Запуск и интерфейс

```python
from pathlib import Path
from analytics.clustering import load_inputs, run as cluster
from analytics.priority import run as score
from analytics.resilience import run

edges, nodes = load_inputs(Path("data"))
node_clusters, _ = cluster(edges, nodes)
priority = score(edges, nodes, node_clusters)
result = run(edges, nodes, priority)  # 100 случайных прогонов каждого типа
print(result["comparisons"].query("n_removed == 20").to_string(index=False))
```

Входы: `edges[src,dst,sum_kzt]`, `nodes[gid,depth,is_seed]`,
`priority[gid,priority_score]`. Дополнительные колонки допускаются.
priority должен содержать ровно один score 0..1 для каждого узла. Дубликаты,
неизвестные концы рёбер, пропуски, нецелые gid, нечисловые/неположительные веса
и неверные настройки отклоняются. Gid сохраняются как целые (без float).

`run(..., steps=None, random_runs=100, seed=42)` возвращает словарь:

| Ключ | Содержание |
|---|---|
| `baseline` | DataFrame, исходные метрики до удаления |
| `scenarios` | Строка на strategy/trial/n_removed, все метрики каждого прогона |
| `summary` | strategy/n_removed/metric, mean/q05/q95, n_trials и n_valid |
| `comparisons` | Приоритет против каждого контроля для трёх основных метрик |
| `removals` | strategy/trial/rank/gid: порядок удаления до максимального N |
| `metadata` | Настройки, версия NetworkX и оговорка об интерпретации |

По умолчанию N = 0, 1, 5, 10, 20, 50; для маленьких графов исключаются
недостижимые размеры. Пользовательские steps валидируются, сортируются,
повторы убираются, N=0 добавляется всегда. N=число всех узлов допустимо.
Таблицы можно сохранить отдельным вызывающим кодом или показать в бонусном
экране. Модуль не создаёт никаких файлов, включая обязательные CSV.

## Сценарии и воспроизводимость

Удаление узла означает удаление всех его входящих и исходящих рёбер.
Рёбра между оставшимися узлами сохраняют исходные суммы. Порядок фиксирован
по исходному графу: скоринг и degree после удаления НЕ пересчитываются.

- `priority`: score по убыванию, числовой gid по возрастанию при равенстве.
  Порядок проверяется тестом против `analytics.top_nodes.rank_candidates`.
- `degree`: in_degree + out_degree, затем gid. Это простой структурный контроль,
  который может оказаться сильнее AML-приоритета; обратные рёбра учитываются
  отдельно, петля даёт два конца.
- `random`: равновероятная выборка без возвращения из ВСЕХ узлов, включая
  исходные изоляты и boundary-узлы. 100 независимых перестановок.
- `matched_random`: 100 перестановок внутри групп `(is_seed, depth)`.
  Каждый префикс имеет ровно такой состав seed/depth, как соответствующий
  priority top-N. Это контролирует часть смещения от способа обхода графа.

У одного trial все N используют вложенные префиксы одного порядка. Для двух
случайных контролей применяются разные потоки NumPy RNG с фиксированным seed.
Перед вычислениями gid/рёбра сортируются; перестановка строк не меняет результат.
Для воспроизведения нужны те же данные, priority, параметры и версии зависимостей.

## Метрики: что именно «распалось»

Граф остаётся направленным и взвешенным. Слабая связность намеренно игнорирует
направление только для вопроса о фрагментах; сильная связность и достижимость
сохраняют направление. Используются стандартные компоненты
[NetworkX: weak](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.components.weakly_connected_components.html)
и [strong](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.components.strongly_connected_components.html).

### 1. Потеря связности между сохранившимися узлами — weak_pair_loss

Пусть S — оставшиеся узлы. B — число неупорядоченных пар из S, находившихся
в одной слабой компоненте ДО удаления. A — число таких пар ПОСЛЕ удаления.
Тогда `weak_pair_loss = 1 − A/B`. Пары считаются через суммы `k*(k−1)/2`
по размерам компонент; перечислять все пары не нужно.

Это отделяет распад от простого сокращения числа узлов. Например, удаление
концевого листа цепочки даёт 0 потери, а удаление середины — положительную
потерю среди оставшихся. Изначально разобщённые пары не включаются в B.
При B=0 результат NaN, а не «нулевой ущерб». Для разных N меняется знаменатель:
монотонность доли не гарантируется даже при вложенных удалениях.

### 2. Потеря направленной достижимости от seed — seed_reach_loss

Для каждого сценария берутся только СОХРАНИВШИЕСЯ seed. B — оставшиеся
не-seed узлы, достижимые от хотя бы одного такого seed в исходном графе;
A — те же достижимые узлы после удаления. Доля потери — `1 − |A|/|B|`.
В исходном графе путь может идти через удаляемые узлы, в том числе через
удаляемый seed. Сами удалённые цели не входят в знаменатель.

Так удаление seed не выдаётся автоматически за разрыв всех его исходных
маршрутов: сравниваются одни и те же оставшиеся источники и цели. Если
источников/достижимых целей нет, доля NaN. Это объединённая доступность от
любого seed, не число путей и не сумма отдельных достижимостей каждого seed.
`n_seed_remaining`, `seed_reachable_before/after` позволяют проверить знаменатель.

### 3. Доля исторического оборота на удалённых рёбрах — removed_kzt_share

`1 − оставшаяся сумма sum_kzt / исходная сумма`. Каждое направленное ребро
считается один раз, даже если удалены оба конца; встречные рёбра считаются
отдельно. Самопетли также считаются один раз. Это оборот исторических переводов,
не объём предотвращённых будущих операций и не оценка максимального потока.
При нулевом исходном обороте доля NaN. Дополнительно возвращаются абсолютные
`remaining_kzt` и `removed_kzt` (KZT).

### Дополнительные метрики

Число слабых компонент, размеры крупнейших слабой и сильной компонент,
доля крупнейшей слабой компоненты относительно исходного числа узлов,
число оставшихся узлов/рёбер, изоляты и НОВЫЕ изоляты среди оставшихся узлов.
19 исходных изолированных seed в новом ущербе не учитываются. Одного числа
компонент недостаточно: оно может уменьшиться при удалении целой компоненты.

`summary.q05/q95` — эмпирические перцентили случайных сценариев, НЕ доверительный
интервал среднего. NaN исключаются, число применимых сценариев указано в n_valid.
`comparisons.priority_minus_reference` положительно, когда приоритет разрушает
больше по данной метрике. `reference_fraction_ge_priority` — доля применимых
контрольных сценариев с ущербом не меньше приоритета, не p-value. Ноль из
100 не означает нулевую вероятность и не доказывает статистическую значимость.
При неприменимом сравнении возвращается NaN.

## Результат на предоставленном графе

Замер 23 сентября 2026: база ветки `89a8358`, Python 3.11, NetworkX 3.6.1,
seed=42, 100 прогонов каждого случайного контроля, N=0/1/5/10/20/50.
Загрузка, кластеризация, скоринг и весь эксперимент заняли **28.4 секунды**
на текущей машине (лимит 5 минут выполнен). Увеличение random_runs/числа steps
увеличивает время; для произвольно больших графов гарантия 5 минут не заявляется.

Исходно: 2 248 узлов, 3 119 рёбер, 35 слабых компонент; крупнейшая — 1 877 узлов,
крупнейшая сильная — 85 узлов, 19 изолятов, оборот 365 890 012.01 KZT.

При N=20 (0.89% узлов):

| Удаление | Потеря связности пар | Потеря достижимости от seed | Оборот удалённых рёбер | Новые изоляты |
|---|---:|---:|---:|---:|
| Priority | **54.87%** | **56.76%** | **27.75%** | **259** |
| Degree | 59.99% | 64.72% | 30.28% | 570 |
| Random, среднее | 1.90% | 1.04% | 1.76% | 12.85 |
| Matched random, среднее | 4.18% | 2.38% | 2.78% | 29.30 |

У matched random 5–95-й перцентили потери связности пар — 0.83–10.04%,
потери достижимости — 0.37–5.82%, оборота — 0.95–5.82%.
Ни один из 100 matched random прогонов не достиг эффекта priority top-20
по этим трём метрикам. После priority top-20 крупнейшая слабая компонента
остаётся размером 1 231, сильная — 7, всего слабых компонент становится 413.
Граф сильно фрагментируется, но большая связанная часть сохраняется.

| Priority N | Крупнейшая слабая компонента | Потеря связности пар | Потеря достижимости | Оборот удалённых рёбер |
|---:|---:|---:|---:|---:|
| 0 | 1877 | 0% | 0% | 0% |
| 1 | 1818 | 5.96% | 3.09% | 3.40% |
| 5 | 1643 | 22.49% | 16.94% | 10.44% |
| 10 | 1452 | 38.69% | 27.21% | 19.90% |
| 20 | 1231 | 54.87% | 56.76% | 27.75% |

Формулировка для демо: «Гипотеза: наш топ выделяет структурно важные узлы
наблюдаемого графа. Удаление 20 узлов разрывает 54.9% связанных пар среди
оставшихся против 4.2% у случайных узлов с тем же составом seed/depth.
Это поддерживает выбор узлов для проверки. При этом обычный degree разрушает
сеть сильнее — 60.0%: AML-приоритет не оптимизирует максимальное разрушение».

## Границы вывода и проверки

- Выгрузка только за июль и только по исходящему обходу с порогом 5 000 KZT.
  Невидимые связи могут вновь соединить наблюдаемые фрагменты. Матчинг seed/depth
  уменьшает одну причину смещения, но не восстанавливает отсутствующие данные.
- У seed и части других узлов вход неполон. На depth=4 отсутствие исходящих —
  граница наблюдения, не доказательство оседания. Метрики относятся к выгрузке.
- Направленная достижимость на агрегированном месяце не доказывает, что деньги
  прошли путь в правильном временном порядке; даты здесь не моделируются.
- Удаление статическое: перенаправление потоков и адаптация участников неизвестны.
  Связность, оборот и высокий score не доказывают виновность и не являются
  рекомендацией автоматически блокировать счета.
- Контроль degree показывает структурную альтернативу, а случайные контроли —
  эффект относительно фона. Эксперимент не независимая валидация AML: приоритет
  сам включает degree/объём/связи кластеров. Проверяется структурное следствие.

`python -m pytest tests/test_resilience.py` проверяет цепочку, мост, лист,
направление, цикл, встречные рёбра/петлю, старые изоляты, исчезновение seed,
пустой остаток, граф без рёбер, настройки и ошибки входов. Также проверяются
повторяемость при перемешивании строк, отсутствие изменения входов, состав
matched random каждого префикса, произвольная замена gid, совпадение топа с
PAN-37 и интеграция с PAN-35/PAN-36 на реальных данных. Отдельный тест показывает,
что сравнение корректно возвращает проигрыш приоритета degree на звезде.
Тест интеграции также ищет литералы реальных gid в модуле (числа и числа
в строках); без data/ только он пропускается.
Произвольную скрытую зависимость от gid этот предохранитель не доказывает.
