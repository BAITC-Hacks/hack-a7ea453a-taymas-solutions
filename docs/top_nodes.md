# Top узлов и аналитические проверки (PAN-37)

`analytics.top_nodes.run(priority, nodes_roles, top_n=20)` возвращает DataFrame
с колонками `rank, gid, role, priority_score, why`. Модуль ничего не пишет на диск
и не импортирует незавершённые модули скоринга или классификации ролей.

Вход `priority` — результат согласованного
`analytics.priority.run(edges, nodes, node_clusters)`: `gid, priority_score, why`.
Второй вход содержит как минимум `gid, role`; оба входа должны иметь ровно одну
строку на каждый gid и одинаковое покрытие. Если второй вход уже содержит
`priority_score`, проверяется точное совпадение с PAN-36 по gid. При итоговой
сборке используйте один результат PAN-36 для обеих таблиц, без округления.
Роли строго из словаря ТЗ. Пустые роли/объяснения, неизвестные gid, дубликаты,
NaN/inf и score вне 0–1 приводят к ValueError; заглушки не подставляются.

## Почему узел стоит на своём месте

Сначала `priority_score` по убыванию, затем числовой `gid` по возрастанию.
При равном score gid — только технический способ разрешения равенства,
а не дополнительный AML-сигнал. `why` передаётся из PAN-36 дословно:
PAN-37 не меняет формулу и не придумывает объяснений. Проверка непустого текста
не доказывает его аналитическую корректность — за соответствие why формуле
отвечает PAN-36. Выбираются первые top_n строк; по умолчанию 20. top_n меньше
20, нецелое или больше числа доступных узлов — ошибка.

Кластерные квоты не применяются: они вытесняли бы узлы с большим score.
`audit` сообщает число представленных кластеров, долю покрытия и список
отсутствующих кластеров. Неполное покрытие в top-20 допустимо. При необходимости
аналитик увеличивает top_n, сохраняя общий порядок приоритета.

## Подключение в общий pipeline

```python
from analytics.top_nodes import run as build_top, audit

# priority — результат PAN-36; nodes_roles — итог PAN-34 с его score.
top_nodes = build_top(priority, nodes_roles)
report = audit(top_nodes, priority, nodes_roles, edges, nodes,
               node_clusters, clusters)
# Запись top_nodes.to_csv(..., index=False) выполняет общий pipeline.
```

Для audit у nodes_roles нужны `gid, role, priority_score, cluster_id, in_kzt,
out_kzt`. Остальная схема и evidence проверяются в PAN-34. Аудит проверяет:

- точный top-N, непрерывный rank, совпадение ролей/score/why и порядок;
- полное покрытие исходных узлов в priority, ролях и назначениях кластеров;
- соответствие cluster_id, n_nodes и n_seed по каждому кластеру;
- отсутствие неизвестных концов рёбер и повторяющихся направленных пар;
- входящие/исходящие суммы каждого узла, включая нули изолированных узлов;
- внутренний оборот каждого кластера и внешние потоки, если соответствующие
  колонки присутствуют в clusters. Денежный допуск 0.011 KZT, rtol=0;
- отчёт об обороте внутренних и межкластерных рёбер. Их сумма — общий оборот;
  сумма одних внутренних рёбер обычно меньше общего оборота.

Это проверки сумм внутри выгруженного графа, не полного банковского баланса.
Входящие seed неполны, отсутствие исходящих depth=4 не доказывает terminal.
PAN-37 не переопределяет роли и не корректирует score по этим признакам.

## Проверка

`python -m pytest tests/test_top_nodes.py` (целевое окружение Python 3.11,
networkx 3.6.1). Синтетические тесты проверяют испорченные входы, стабильность
при перемешивании строк, переименование gid и отсутствие изменения входов.
Тест на настоящем датасете проверяет кластерные суммы и CSV round-trip;
он использует явно тестовые score/роли, не выдаёт их за готовую AML-аналитику.
Без data/ только этот интеграционный тест пропускается.
