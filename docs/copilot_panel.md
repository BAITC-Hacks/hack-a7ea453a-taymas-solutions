# Панель AML Investigation Copilot (PAN-48)

Справа от графа находятся две вкладки: **Помощник** и существующая **Карточка узла**.
Панель позволяет задать вопрос, проверить факты по CSV и перейти к упомянутому узлу.
Результат — гипотеза для проверки. Роли и приоритеты не пересчитываются в браузере.

## Запуск

Обычный Docker-запуск включает локальный API и React UI; pipeline запускается
после загрузки трёх Parquet через браузер:

```bash
docker compose up --build -d
# http://localhost:8501
```

`copilot` использует активный снимок загруженного набора. NVIDIA не требуется. Ключ и модель,
если нужны, передаются из окружения хоста только Python-сервису во время запуска:
`NVIDIA_API_KEY` и `NVIDIA_MODEL`. Они не входят в image, frontend build и ответ status.
Порт API не публикуется: браузер обращается к нему через nginx на том же origin.
Падение Copilot не мешает nginx показывать граф и CSV. `UI_PORT` позволяет изменить
порт UI, например `UI_PORT=8508 docker compose up --build -d`.

Для разработки, из корня проекта:

```bash
python -m agent_orchestrator.server --out out --state .money-graph
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Vite и `npm run preview` проксируют `/api` на `127.0.0.1:8765`.
API по умолчанию слушает только loopback; `--host 0.0.0.0` используется внутри Docker.
Он предназначен для локального демо, не для публичного сервиса.
После загрузки через браузер граф и снимок Copilot обновляются автоматически;
перезапуск не нужен. До загрузки помощник сообщает, что данные ещё не готовы.
При первом старте существующий `out/` импортируется как версия; дальнейший batch
не меняет активный снимок — используйте загрузку. [Контракт версий](uploads.md).

Без локального сервиса UI показывает «Нет связи с помощником», вопрос можно повторить
после запуска API; граф, фильтры и карточки продолжают работать. Статический `/fixtures`
содержит отдельные демонстрационные значения: запросы помощнику для него отключены,
чтобы не смешать их с реальными данными `out/`.

## Как пользоваться

- «Почему этот узел в топе?» подставляет текущий выбранный узел; без выбора — первый из топ-листа.
- «Кто общий сборщик?» использует добавленные в контекст gid. Добавьте минимум два узла.
- «Какой следующий шаг проверки?» работает с выбранным контекстом; без него показывает очередь проверки.
- До пяти gid можно добавить вручную или кнопкой «Выбранный на графе». Все идентификаторы остаются строками.
- Подсказка заполняет вопрос. Расчёт запускается только кнопкой «Разобрать вопрос».
- Флажок «Использовать AI» доступен, когда сервер сообщает о настроенном окружении NVIDIA;
  это не проверка квоты или успешности внешнего API. По умолчанию флажок выключен.
- При timeout/quota/API error NVIDIA показывается проверенный локальный ответ с причиной перехода.
  При недоступности самого локального API показывается ошибка с возможностью повторить вопрос.

Ответ содержит summary, кандидатов с role/priority_score, следующий шаг, факты с
`nodes_roles.csv` / `edge_table.csv` и точными колонками, ограничения данных.
Клик по любому gid открывает карточку PAN-39 и центрирует граф на этом узле.
Узлы и направленные рёбра из claims подсвечены мятным цветом. Если узел скрыт
фильтром или лимитом, он временно добавляется на граф; полоса над графом показывает
количество таких узлов. Фильтры не сбрасываются. «Убрать подсветку» снимает это добавление.

## Контракт и проверка фактов

`GET /api/copilot/status` возвращает `{ready, nvidia_available, dataset_id}`. Он не вызывает LLM.
`POST /api/copilot/answer` принимает `question`, `selected_gids`, `use_nvidia` и опциональный `depth`
по `agent_orchestrator.Request`, а также заголовок `X-Dataset-Version` текущего
набора. Ответ помечен той же версией; устаревший запрос получает HTTP 409.
Возвращается `for_browser(run(...))` из PAN-46.
Сервис не принимает пути к файлам, произвольные инструменты и конфигурацию ключа из запроса.

До отображения и подсветки клиент проверяет:

1. `verification=passed` от PAN-47, известные status/provider и отметку «гипотеза для проверки».
2. Строковые gid, существование узлов/рёбер в загруженной выгрузке и покрытие списка gids.
3. Каждый claim: значение, файл, колонку и точный gid либо пару src/dst. Допуск суммы — 0.01 KZT,
   остальных чисел — 1e-6, как у verifier. Кандидаты сверяются с текущими role/priority_score.
4. Индексы evidence и обязательные предупреждения о границе depth=4.

При несовпадении ответ скрыт целиком. Summary и все остальные строки выводятся обычным
React-текстом, без HTML-интерпретации. Ни ключ, ни весь датасет браузер в API не отправляет.
Статусы loading, empty, fallback, error различаются. Отмена или размонтирование панели
прерывает ожидание; запоздавший ответ не заменяет новый и не подсвечивает старые узлы.

Лимиты: вопрос 1000 символов; контекст 5 gid; HTTP request 8192 байта; response 100 000 байт
с контролем читаемого потока; браузерный timeout 15 секунд; одновременно до двух запросов
к оркестратору. Сохраняются лимиты graph tools/NVIDIA из [PAN-46](agent_orchestrator.md).

## Проверки

```bash
python -m pytest tests -q
cd frontend
npm test
npm run build
```

Unit-тесты UI проверяют отправку, точность gid, fallback при quota, empty/error, повтор,
отмену, ограничения, переход по gid, несовпадающие факты, timeout и сохранение фильтров.
Python HTTP-тесты используют настоящие tools/verifier и проверяют read-only по sha256 CSV,
границы запроса, ошибки и отсутствие credentials в status. Ключ NVIDIA им не нужен.

Для browser smoke нужны настоящие `out/*.csv`, запущенные API и UI:

```bash
cd frontend
npx playwright install chromium   # однократно, если браузер ещё не установлен
npm run dev -- --host 127.0.0.1 --port 5178 --strictPort
# в другом терминале, из frontend:
npm run test:e2e
# либо против Docker:
COPILOT_UI_URL=http://127.0.0.1:8501 npm run test:e2e
```

Три browser-теста выбирают gid из текущих CSV, проходят целевые вопросы, переход
в карточку при активном фильтре и ошибку API. Снимки интерфейса сохраняются в
игнорируемом `frontend/test-results/`. Успешный локальный тест не заменяет live smoke NVIDIA.

## Демо на 90 секунд

Перед показом запустите pipeline/UI/API. Подготовьте два gid из входящих переводов
одного узла с несколькими плательщиками; берите их из текущего графа, не из фиксированного списка.

| Время | Действие | Что показываем жюри |
|---|---|---|
| 0–15 с | Откройте первый узел топ-листа, вкладку «Помощник», нажмите первую подсказку и отправьте вопрос | Объяснение приоритета из локальных числовых фактов |
| 15–30 с | Раскройте факты, покажите файл/колонку и нажмите gid кандидата | Переход в существующую карточку и фокус графа, проверяемость вывода |
| 30–55 с | Вернитесь в помощник, уберите прежний контекст, добавьте два подготовленных gid и задайте вопрос про общего сборщика | Кандидаты, прямые переводы, подсветка связей, гипотеза для проверки |
| 55–75 с | Оставьте одного кандидата в контексте и отправьте подсказку о следующем шаге | Конкретное действие аналитика и ограничения наблюдаемого графа |
| 75–90 с | Покажите индикатор «Локальный ответ», измените фильтр и перейдите по gid из ответа | Работа без NVIDIA и явное добавление нужных узлов вне фильтра |

Для показа устойчивости остановите только `copilot` (`docker compose stop copilot`),
повторите вопрос и измените фильтр: панель сообщает об ошибке, граф остаётся рабочим.
Вернуть сервис: `docker compose start copilot`.
