# Загрузка исходных данных (PAN-58)

Локальное приложение принимает три файла `nodes.parquet`, `edges.parquet`,
`transactions.parquet`. ZIP сначала распакуйте. Схема — [DATA_README.md](DATA_README.md).
Каждый файл — не более **10 МиБ** (10 × 1024² байт), весь multipart-запрос —
не более **32 МиБ**, включая служебные заголовки. Ограничения проверяются на
клиенте, Python API и nginx. Файлы не отправляются во внешний API.

## Сценарий аналитика

1. Запустить `docker compose up --build`, открыть <http://127.0.0.1:8501>.
2. Выбрать три файла. До отправки любой из них можно заменить.
3. Нажать «Построить граф». Приложение показывает загрузку, проверку входа,
   расчёт и готовность. Кнопка блокируется на время задания.
4. После успешного расчёта открывается новый граф. CSV можно скачать из интерфейса,
   вопросы Copilot используют тот же набор. Загрузка и расчёт имеют отдельное время.
5. Для повторного анализа нажать «Загрузить другой набор».

Повреждённый Parquet, неверные поля/типы, неизвестные gid, несовпадение сумм или
числа транзакций и превышение лимита возвращают ошибку. Исправьте указанный файл
и повторите. Предыдущий успешный граф остаётся доступен.

## Согласованность

Используется тот же `money_graph.pipeline.run`, что и в CLI. Формулы не меняются.
Сервер хранит вход в каталоге задания со случайным серверным идентификатором;
имена файлов фиксированы. Одновременно принимается только одно задание.
Публикация новой версии происходит после проверки всех CSV и подготовки снимка
Copilot. `active.json` заменяется атомарно. Перезапуск восстанавливает последний
успешный набор, старые CSV остаются неизменными для уже открытых вкладок.

React читает все четыре CSV по URL одной версии и только затем заменяет граф,
сбрасывает фильтры, выбранные gid, ответы и подсветку. Copilot получает заголовок
`X-Dataset-Version` и возвращает версию использованного снимка. Запрос по устаревшей
версии отклоняется; запоздавший ответ не применяется к новому графу.
Для другой открытой вкладки после смены набора требуется обновление страницы.

Локальное состояние — `.money-graph/`, в Docker — volume `datasets` проекта Compose.
Вход и результаты не включаются в Git и Docker image. История автоматически не
удаляется: размер хранилища растёт с каждым новым успешным набором.
Это локальный сервис одного аналитика, без аккаунтов и публичного доступа.

## HTTP API

Все маршруты доступны на origin UI. Прямой Python API слушает `127.0.0.1:8765`.

| Запрос | Результат |
|---|---|
| `GET /api/datasets/active` | `{dataset_id, files_base, job}`; без данных первые два поля `null` |
| `POST /api/datasets/jobs` | multipart с тремя частями `nodes`, `edges`, `transactions`; `202` и Job |
| `GET /api/datasets/jobs/{job_id}` | актуальный Job |
| `GET /api/datasets/{dataset_id}/files/{filename}` | CSV указанной версии |
| `GET /api/copilot/status` | `ready`, `nvidia_available`, `dataset_id` |

Части multipart должны содержать соответствующие имена `nodes.parquet`,
`edges.parquet`, `transactions.parquet`. Повторяющиеся части запрещены.
Job содержит `job_id`, `state` (`validating`, `running`, `ready`, `error`),
`dataset_id`, `error`, `elapsed_seconds`. Время расчёта начинается после получения
загрузки; статус загрузки и её длительность показывает браузер.
Ошибка HTTP для загрузки: `{error: "понятное описание"}`; `409` — задание уже
выполняется, `413` — превышен размер, `400` — некорректный запрос.
Ошибка расчёта отражается в Job с `state=error`, активный набор не меняется.

Разрешённые выгрузки: `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`,
`edge_table.csv`. Произвольные пути и скачивание исходных Parquet не поддерживаются.
Copilot принимает прежний JSON-контракт и дополнительный заголовок
`X-Dataset-Version`; до появления данных отвечает `503`, для устаревшей версии `409`.

## Проверки

```bash
python -m pytest tests -q
cd frontend
npm ci
npm test
npm run build
```

Полный браузерный сценарий (API и UI уже запущены; три Parquet лежат в `data/`):

```bash
cd frontend
npx playwright install chromium
COPILOT_UI_URL=http://127.0.0.1:8501 npm run test:e2e -- upload.spec.ts
```

Для входа из другой папки задайте `UPLOAD_DATA_DIR` абсолютным путём.
Для дополнительного браузерного теста смены данных укажите `UPLOAD_SECOND_DATA_DIR`
с другим валидным набором; без него этот отдельный сценарий пропускается.
Браузерный тест меняет активный набор на загруженный. HTTP smoke Docker:
`./scripts/docker-smoke.sh`. Backend-тесты дополнительно проверяют смену набора,
сохранение предыдущего при сбое, повторы, детерминизм, лимиты и версию Copilot.
Совпадение CLI/UI CSV проверяется в одном Python-окружении; разные ОС могут
различаться в последних знаках float (см. основной README).

Побайтовое сравнение на данных организаторов (локальные API и CLI должны работать
в одном Python-окружении; порт 5178 — адрес вашего Vite):

```bash
python -m money_graph --data data --out out --check-repro
python scripts/upload-smoke.py --url http://127.0.0.1:5178 --data data --compare-out out
python scripts/upload-smoke.py --url http://127.0.0.1:5178 --data data --compare-out out
```
