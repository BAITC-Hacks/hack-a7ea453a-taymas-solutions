# Входные данные, таблица рёбер и признаки узлов (PAN-32)

```bash
python -m money_graph --data data --out out
```

## 1. Контракт входных данных

`money_graph/io.py` проверяет три parquet до любых расчётов. Ошибки собираются все сразу: прогон останавливается с полным списком и кодом выхода 2. Если папки или файлов нет, выводится понятное сообщение, а не traceback.

**Ошибки (прогон останавливается):**

| Проверка | Условие |
|---|---|
| колонки | `edges: src, dst, sum_kzt, n_tx, depth`; `nodes: gid, depth, is_seed`; `transactions: src, dst, date, sum_kzt` |
| пропуски | в обязательных колонках нет пустых значений |
| типы | `gid/src/dst/n_tx/depth` — целые, `sum_kzt` — число, `is_seed` — bool, `date` читается как дата ISO |
| дубликаты | `gid` уникален в nodes; пара `src→dst` уникальна в edges (это агрегат пары) |
| покрытие gid | каждый `src`/`dst` из edges и transactions есть в nodes |
| домены | `sum_kzt > 0`, `n_tx ≥ 1`, `nodes.depth ∈ 0..4`, `edges.depth ∈ 1..4`, `is_seed ⇔ depth = 0` |
| сверка агрегатов | edges и transactions совпадают по набору пар, сумме (допуск 0.01 KZT) и числу переводов |

**Предупреждения (прогон продолжается, текст попадает в отчёт проверки):**

| Что | На датасете | Как учитывается |
|---|---|---|
| полностью повторяющиеся транзакции (пара, день, сумма) | 97 | не удаляются: `n_tx` их учитывает; по рёбрам — `n_repeat_tx`, возможный признак дробления |
| узлы без рёбер | 19 (все seed) | входят в выгрузку, роль `peripheral`, правило `isolated` |
| узлы 4-го колена | 444 | исходящие не выгружались → `boundary_depth4`, роль `terminal` для них запрещена |
| переводы ниже порога 5 000 KZT | 0 | проверка порога выгрузки |
| `edges.depth ≠ depth(src)+1` | 0 | выгрузка собрана не обходом от seed |
| переводы самому себе | 0 | — |

После проверки типы приводятся к каноническим: целые → `int64`, суммы → `float64`, дата → `datetime64` с точностью до дня. Исходные DataFrame при этом не меняются.

## 2. Единицы измерения

| Величина | Единица |
|---|---|
| `*_kzt` | тенге, сумма за июль 2026, только внутрибанковские переводы ≥ 5 000 KZT **внутри графа** |
| `*_tx`, `n_tx` | число отдельных переводов |
| `*_deg`, `n_payers`, `n_receivers` | число **уникальных** контрагентов |
| `*_days`, `median_lag_days` | календарные дни (в данных только дата, без времени) |
| `*_share`, `pass_through*` | доля 0–1 (`pass_through` может быть > 1: узел отдал больше, чем получил в графе) |
| `pagerank`, `hub_score`, `authority_score` | нормированы: сумма по всем узлам = 1 |
| `betweenness` | нормированная, 0–1 |

## 3. Пустые входящие и исходящие потоки

Правило: **счётчики и суммы при отсутствии потока равны 0, а неопределённые отношения — `NaN`** (пустая ячейка в CSV). Нулём такие отношения не заменяются, потому что 0 означал бы «удержал всё» или «ничего не отдал быстро», а это ложный сигнал.

| Колонка | Нет входящих | Нет исходящих |
|---|---|---|
| `in_deg, in_kzt, in_tx`, `out_*` | 0 | 0 |
| `avg_in_tx_kzt` / `avg_out_tx_kzt` | 0 | 0 |
| `pass_through` | NaN | 0 (если есть вход) |
| `pass_through_reliable` | NaN; также NaN у seed (вход занижен) и у depth=4 (выход не виден) | 0 |
| `top_payer_share` / `top_receiver_share` | NaN | NaN |
| `fast_out_share`, `median_lag_days` | NaN (нет поступления до перевода) | NaN |
| `sync_payers_max` | 0 | — |
| `min_cycle_len` | 0 — узел не входит ни в один цикл | |

Обязательные колонки выгрузки (`gid, role, role_score, cluster_id, priority_score, evidence`) не бывают пустыми — это проверяется при каждом запуске.

## 4. Граница обхода

| Колонка | Смысл |
|---|---|
| `boundary_depth4` | узел на 4-м колене: его исходящие **не выгружались**, `out_deg = 0` ничего не говорит о том, осели ли деньги |
| `out_observable` | `not boundary_depth4`: у узлов depth ≤ 3 исходящие выгружены полностью (рёбра 4-го колена выходят именно из depth = 3) |
| `in_underestimated` | seed: входящие извне выборки не видны |
| `truncated_by_depth` | колонка из starter: `boundary_depth4 и out_deg = 0` (на датасете совпадает с `boundary_depth4`) |
| `boundary` | итог: `full` / `out_hidden` (depth=4) / `in_hidden` (seed) / `isolated` (нет рёбер) |
| `external_inflow_suspected` | не seed, отдал > 1.2 × полученного в графе → у денег есть источник вне выгрузки |

## 5. Таблица направленных рёбер: `out/edge_table.csv`

Одна строка на пару плательщик → получатель (3 119 строк). Используется для сборки графа и для связей в карточке узла.

| Колонка | Смысл |
|---|---|
| `src, dst, sum_kzt, n_tx, depth` | из `edges.parquet` |
| `avg_tx_kzt`, `max_tx_kzt` | средний и крупнейший перевод пары |
| `n_repeat_tx` | переводов, в точности повторяющих другой перевод пары в тот же день |
| `first_date`, `last_date`, `active_days` | когда пара была активна |
| `src_depth`, `dst_depth`, `src_is_seed`, `dst_is_seed` | колено и seed-статус концов |
| `is_back_edge` | `dst_depth ≤ src_depth`: деньги идут к узлу, найденному раньше (745 рёбер) |
| `is_reciprocal` | есть обратное ребро `dst → src` (354 ребра) |
| `share_of_src_out`, `share_of_dst_in` | доля ребра в исходящем потоке плательщика и во входящем потоке получателя |

## 6. Признаки узла

Полный список колонок `nodes_roles.csv` после обязательных: базовые из starter, контрагенты, центральности, граница, время, циклы. Описаны в README, раздел «Признаки узла». Пороги — в `money_graph/config.py`.
